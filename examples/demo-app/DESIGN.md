# FailWatch 故障演示商城 · 界面设计文档（v1）

> 定位：**故障演示商城**——每个交互故意触发标注的错误，用于演示 FailWatch 监控能力。
> 设计目标：①像真商城（可信）②错误触发方式页面可见（可发现性）③移动优先（演示时手机也能操作）。

## 1. 设计原则

| 原则 | 落地 |
|---|---|
| 故障即功能 | 错误标注不是"破坏感"，是"演示说明书"——设计成清晰的警示徽标，不吓人但醒目 |
| 可发现性 | 每个操作旁标注触发的错误（类型+状态码），不靠记忆 |
| 移动优先 | 320px 起步：单列 → 2 列（768px）→ 4 列（992px） |
| 诚实 | 页面顶部总说明条："本页面故意触发错误，用于演示监控" |

## 2. 配色方案（暖赤陶商城感 + 错误语义色）

### 品牌主色：赤陶（Terracotta）——温暖、消费感，与 Interview Forge 风格呼应

| Token | 色值 | 用途 |
|---|---|---|
| `terracotta-50` | `#FDF3EE` | 页面底色（暖白） |
| `terracotta-100` | `#FAE4D8` | 卡片 hover 底 |
| `terracotta-500` | `#D96C3F` | **品牌主色**：按钮/链接 |
| `terracotta-600` | `#C45A2F` | 按钮 hover/按下 |
| `terracotta-700` | `#A64A26` | 文字强调 |

### 中性灰（暖灰，与赤陶协调）

| Token | 色值 | 用途 |
|---|---|---|
| `stone-50` | `#FAF9F7` | 卡片底 |
| `stone-200` | `#E7E5E4` | 边框/分隔线 |
| `stone-500` | `#78716C` | 次要文字 |
| `stone-800` | `#292524` | 主文字（对比度 12:1 ✅） |
| `stone-900` | `#1C1917` | 标题 |

### 错误语义色（核心！按严重度分层，全部满足 WCAG 4.5:1）

| 错误 | Token | 色值 | 对比度（白底） | 对应场景 |
|---|---|---|---|---|
| critical（500） | `red-600` | `#DC2626` | 5.0:1 ✅ | 接口 500 库存崩 |
| high（502/503） | `orange-600` | `#EA580C` | 4.5:1 ✅ | 网关/过载 |
| medium（404/JS/Promise） | `amber-600` | `#D97706` | 4.8:1 ✅ | 接口不存在/逻辑错 |
| low（资源） | `sky-700` | `#0369A1` | 6.3:1 ✅ | 图片加载失败 |

> **规则**：错误标注 = 语义色 + 文字（**禁止只靠颜色传达**——色盲用户靠文字也能看懂）。

## 3. 字体方案（8px 基线模块化刻度）

| 用途 | 字号 | 字重 | 行高 |
|---|---|---|---|
| 页面标题 | 24px | 600 | 32px |
| 商品名 | 16px | 600 | 24px |
| 价格 | 18px | 700 | 24px（数字 tabular-nums） |
| 错误标注 | 13px | 500 | 20px |
| 说明文字 | 14px | 400 | 22px |

**字体栈**（系统优先，中文 PingFang SC 自动回退）：
```css
font-family: -apple-system, 'PingFang SC', 'Microsoft YaHei', 'Segoe UI', sans-serif;
```
**数字**（价格/状态码）：`font-variant-numeric: tabular-nums`（等宽数字，排序/跳动不抖动）。

## 4. 布局（移动优先栅格）

```
320px（单列）    768px（2 列）     992px+（4 列）
┌────────┐      ┌────┬────┐      ┌──┬──┬──┬──┐
│ 品牌栏  │      │ 商品│ 商品│      │商品×4 并排 │
│ 说明条  │      ├────┼────┤      └──┴──┴──┴──┘
│ 商品1  │      │ 商品│ 商品│
│ 商品2  │      └────┴────┘
│ 结算/  │
│ 详情   │
└────────┘
```

**栅格实现**（免媒体查询响应式）：
```css
.product-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
  gap: 16px; /* 8px 倍数 */
}
```

**页面结构（从上到下）**：
1. **品牌栏**：🛍️ FailWatch 故障演示商城（固定顶部）
2. **说明条**（琥珀底浅色）："⚠️ 本页面故意触发错误，用于演示监控——点下方操作会真实上报"
3. **商品区**：4 张商品卡（图+名+价+加购按钮+错误标注）
4. **操作区**：「去结算」（Promise 失败）「查看详情」（JS 错误）
5. **底部**：小字 "Powered by FailWatch SDK"

## 5. 组件清单与状态

### 商品卡（核心组件）
| 部分 | 状态 |
|---|---|
| 商品图 | 故意引用不存在图片 → `onerror` 上报资源错误；**占位符显示**（避免破图丑） |
| 加购按钮 | 默认（赤陶 500）→ hover（600）→ 按下（700 + 0.95x 收缩）→ 点击后 loading（骨架条）→ 失败提示（红色 toast） |
| 错误标注 | 商品卡右上角徽标：`⚠️ 加购→500`（语义色边框 + 文字） |

### 错误标注规范（每个操作旁）
```
[秒杀款] 加购 → ⚠️ 接口 500（库存服务崩）
[跨境款] 加购 → ⚠️ 接口 502（网关错误）
[限量款] 加购 → ⚠️ 接口 503（服务过载）
[历史款] 加购 → ⚠️ 接口 404（接口不存在）
[去结算]     → ⚠️ Promise 失败（支付未处理）
[查看详情]   → ⚠️ JS 错误（页面逻辑抛错）
（页面加载） → ⚠️ 商品图加载失败（资源错误）
```

## 6. 微交互（克制，仅 transform/opacity）

| 元素 | 动效 | 时长 |
|---|---|---|
| 按钮 | hover 1.05x 放大 / 按下 0.95x 收缩 | 0.2s |
| 点击反馈 | 加购 → 按钮变 loading 骨架 | 0.2s |
| 失败反馈 | 顶部滑入红色 toast（"上报失败已记录"） | 0.3s 滑入 + 3s 自动消失 |
| 商品卡 hover | 轻微上浮（translateY -2px）+ 阴影加深 | 0.25s |

## 7. 无障碍检查清单（WCAG 2.2 AA）

- [ ] 文字对比度 ≥ 4.5:1（正文）/ 3:1（大字号+UI 组件）——配色表已达标
- [ ] **错误信息不只用颜色**：徽标 = 色块 + 文字（"500"）
- [ ] 键盘导航：加购/结算/详情均可 Tab 聚焦 + Enter 触发；焦点可见（`outline: 2px terracotta-500`）
- [ ] 语义化 HTML：商品用 `<article>`、按钮 `<button>`、说明用 `<p>` + `role="status"`（动态 toast）
- [ ] 图片 `alt`：商品图 alt 描述；缺图占位符有文字
- [ ] 标题层级：h1 页面 → h2 商品名，不跳级

## 8. 落地设计 Token（CSS 变量，Tailwind 风格）

```css
:root {
  /* 品牌 */

  /* 中性 */
  --stone-50: #FAF9F7;
  --stone-800: #292524;
  /* 语义（错误分层） */
  --error-critical: #DC2626;
  --error-high: #EA580C;
  --error-medium: #D97706;
  --error-low: #0369A1;
  /* 间距/圆角（8px 基线） */
  --space-2: 8px; --space-4: 16px; --space-6: 24px;
  --radius: 8px;
}
```
